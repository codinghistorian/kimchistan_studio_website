4. PDF·GIF·동영상·링크의 실제 효용

[일반 GIF를 PDF 이미지로 삽입]
Adobe 공식 안내는 GIF를 이미지로 추가하면 정지 그림으로 들어가며, GIF 원본 형식의 애니메이션이 PDF에서 그대로 재생되지 않는다고 설명한다.
따라서 ‘PDF를 열면 GIF가 자동으로 움직인다’는 전제로 제작하지 않는다. PDF에는 의도한 대표 프레임을 명시적으로 넣는다.
공식 근거: https://www.adobe.com/au/acrobat/roc/blog/how-to-add-gifs-to-pdf.html

[PDF 리치미디어로 MP4 삽입]
Adobe는 Acrobat의 Add rich media와 H.264 기반 영상 재생 경로를 제공한다. 영상 포스터와 활성화 설정도 지원한다.
다만 이 문서는 Acrobat 지원 경로를 설명할 뿐 모든 브라우저·플랫폼 내장 뷰어·입찰 첨부 미리보기에서의 동일 재생을 보증하지 않는다. 이번 검토에서는 그 모든 환경을 실행 테스트하지 않았다.
공식 문서는 직접 영상 URL을 넣을 경우 .mp4 또는 .mov 등 영상 파일의 전체 주소를 요구한다. YouTube watch/shorts HTML 페이지를 직접 MP4 주소처럼 넣으면 된다고 설명하지 않는다.
따라서 이번 제출 PDF의 기본 경로로 리치미디어 재생을 채택할 필요는 없다. 사용자 요청의 영상 확인 기능은 웹 링크 카드로 구현할 수 있다.
공식 근거: https://helpx.adobe.com/acrobat/using/adding-multimedia-pdfs.html

[클릭 가능한 포스터와 영상 링크 / 권장]
Adobe는 PDF 사각 영역에 외부 웹 페이지를 여는 링크 동작을 넣는 방식을 지원한다.
실제 프레임 + 재생 표시 + ‘영상 보기’ + 제목·길이를 조합하고 포스터와 버튼 전체에 같은 canonical YouTube URL을 연결한다.
링크를 열지 않아도 본문의 역량 설명을 이해할 수 있어야 한다. 현재 사용자 지정 영상의 링크만 사용하고 연락처·채널 홈·회사 홈페이지 링크를 추가하지 않는다.

[QR / 보조]
QR은 인쇄 또는 다른 기기로 볼 때 같은 영상 URL로 접근할 수 있는 보조 경로다. 같은 기기에서 읽을 때는 클릭 링크를 주 경로로 둔다.
QR에도 위 두 canonical 영상 URL만 인코딩한다. 충분한 크기·대비·여백을 확보하고 생성 후 대상 URL과 실제 디코딩을 확인한다.
